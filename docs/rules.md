# Built-in rules

The historical checker defines stable IDs SCH001–SCH020. The Rust migration preserves those IDs and separates reusable sheet-level checks from project-profile contracts.

| ID | Historical rule | Rust status |
| --- | --- | --- |
| SCH001 | Wire geometry | Implemented: endpoint count, orthogonal segments, zero-length wires, collinear overlap, crossings and unmarked T-junctions |
| SCH002 | Label topology | Implemented: physical wire-island graph, local-label reuse across distinct islands, duplicate-label detection on one island, and hierarchical twig termination |
| SCH003 | Label/wire glyph overlap | Implemented: estimated visible glyph bounds and strict wire-interior intersection |
| SCH004 | Physical net connectivity | Implemented partial: profile-declared direct pin pairs, common-pin groups, and physically separate pin pairs; verifies pin attachment, wire-only connectivity/separation, expected labels, optional one-label cardinality, scoped forbidden labels, and optional exported-netlist commonality/separation |
| SCH005 | Pin orientation | Implemented: checks connected wire axes against embedded pin geometry for selected unit/convert, right-angle rotation, and X/Y mirroring |
| SCH006 | Component spacing | Implemented when group profiles declare `minimum_member_origin_spacing_mm`: enforces Euclidean spacing between placed symbol origins; not a body-clearance check |
| SCH007 | Group metadata | Implemented when profiles provide `kicad_group_uuid`: resolves native KiCad group and verifies placed-symbol membership against declared component references |
| SCH008 | Annotation text-box geometry | Implemented: required geometry/font/margins, sizing, overlap and wire penetration |
| SCH009 | Group containment | Implemented partial, opt-in: checks member origins/pins/fields and symbol primitives, member-connected and frame-crossing wires, frame-overlapping labels/plain text, text boxes, top-level vector graphics and PNG/JPEG bitmap bounds derived from image pixels/PPI/scale; unsupported image encodings and other non-text-box annotations remain pending |
| SCH010 | Symbol field clearance | Implemented partial: estimated visible-field bounds are checked against other fields, own/other embedded symbol bodies, wires, pins, labels and annotation boxes; exact font rendering and maximum field-to-body spacing remain pending |
| SCH011 | Block annotation structure | Implemented: multiline text boxes require a visible border |
| SCH012 | Frame content clearance | Implemented partial: profile-defined inset checks for member origins/pins/fields and symbol primitives, member-connected and frame-overlapping wires, frame-overlapping labels/plain text/text boxes, top-level vector graphics and PNG/JPEG bitmap bounds; unsupported image encodings and other non-text-box annotations remain pending |
| SCH013 | Wire obstacle clearance | Implemented partial: checks wires against selected-unit embedded primitives plus top-level rectangles, polylines/polygons, circles, sampled arcs and flattened Béziers; embedded primitives use finite symbol rotations and X/Y mirrors, vector paths use the 0.01 mm curve tolerances, and PNG/JPEG image bounds are checked as obstacles; also checks intermediate pins, visible Reference/Value text and annotation boxes; geometric checks remain approximations |
| SCH014 | Shared pin/net contracts | Implemented for profile-declared component pins and connector `pin.N` mappings against exported KiCad netlist membership |
| SCH015 | Required no-connect markers | Implemented: verifies each explicit no-connect marker coincides with a transformed embedded placed-symbol pin, including finite non-cardinal symbol rotations; incomplete pin models are conservatively skipped |
| SCH016 | Wire compactness | Implemented: per-group total length of wire segments wholly inside the referenced frame divided by a positive `wire_length_budget_mm`; over-budget results are warnings |
| SCH017 | Circuit documentation | Implemented: group membership, description text-box UUID and document/page/figure or reviewed screenshot evidence |
| SCH018 | Label text collision | Implemented: estimated glyph bounds against other labels, visible symbol fields and annotation boxes |
| SCH019 | Label-kind consistency | Implemented |
| SCH020 | Component function/rationale documentation | Implemented for metadata-declared components |

## Rule boundaries

KiCad native ERC remains the electrical authority. Rust rules must not duplicate pin-type conflicts, undriven power pins, or native unconnected-pin analysis. Rules requiring exact pin-to-net facts must consume KiCad's exported netlist, not infer connectivity from equal label strings.

SCH004 is an opt-in physical contract for profile-declared `direct_wire_pairs`, `common_pin_groups`, and `separate_wire_pairs`. It verifies resolved pin anchors are attached to wire segments for required connections; direct pairs and common-pin groups with `wire_connected` must belong to the same wire-only component. Common-pin groups also require the expected label on each pin component and can require exactly one matching label. With `netlist_connected`, they additionally require every listed pin to resolve to the same exported KiCad net. `separate_wire_pairs` require two distinct declared pins not to share one physical wire-only component when both are attached to wires; `netlist_separate` additionally requires them to resolve to different exported KiCad nets. A label can join separate wire islands in KiCad's logical netlist, but labels do not create physical wire graph edges. These contracts do not infer all physical-net intent automatically or replace native ERC.

SCH004’s physical graph follows SCH001’s explicit-junction contract: an endpoint touching the interior of another segment is not joined to that segment unless a junction marker is present. End-to-end wire segments remain connected without an additional junction marker.

SCH005 intentionally checks only connected-wire axis alignment; KiCad native ERC remains responsible for electrical pin compatibility and unconnected-pin findings. It skips pin-axis checks for non-cardinal symbol rotations rather than guessing a horizontal/vertical axis. Other geometry rules use the full finite rotation where their geometry model permits it.

SCH015 checks no-connect marker placement against embedded pin coordinates after applying finite symbol rotations and supported mirrors. It skips the rule if a placed-symbol pin model is incomplete or its transform cannot be resolved. KiCad native ERC remains responsible for electrical unconnected-pin analysis.

SCH009 checks group member origins/pins/fields and selected-unit symbol primitives, plus any wire segment that belongs to a member-pin wire island or intersects the configured frame. It also checks visible glyph bounds for labels whose anchors or glyph rectangles overlap the frame, top-level plain-text glyph rectangles that overlap the frame, the configured group description, other overlapping text boxes, top-level vector graphics (rectangles, polylines, polygons, circles, arcs and Béziers), and embedded PNG/JPEG images. Bitmap bounds are derived from image pixel dimensions, embedded PPI metadata, stored scale, and the KiCad file-version PPI migration rules; unknown or incomplete image encodings remain unresolved rather than guessed. Primitive arcs/Béziers use the existing 0.01 mm flattened path approximation with stroke half-width margin; label/plain-text glyph rectangles use NewStroke estimates. Labels never create physical wire edges. Wire segments overlapping the frame are checked regardless of member-pin connectivity. Free-standing labels/wires outside the frame, unsupported image formats, other non-text-box annotation types and unresolvable symbol transforms remain outside this rule's coverage. Finite non-cardinal symbol rotations are applied to embedded pin and primitive coordinates; SCH005 continues to skip non-cardinal pin-axis checks. SCH012 applies the configured inset to the same member, wire, label, text and annotation families, with frame-overlapping free-standing geometry included.

SCH010 estimates visible symbol-field text bounds from the stored field position, font size, angle and justification. It checks field-to-field and field-to-annotation-box overlap, field-to-wire and field-to-pin collisions, label-glyph collisions, and intersections with the field's own or another symbol's embedded outline. A Value field fully contained within a closed symbol primitive is allowed. The bounds are estimates rather than KiCad's exact rendered glyph geometry; the historical maximum-distance-to-body rule and exact gaps are not implemented.

A rule ID is not considered ported merely because it appears in the catalogue. A rule becomes implemented only when it has positive and negative tests and a documented analysis model.
