## Descriptor catalogue

The core crate exports `builtin_rule_registry()`, which builds one descriptive `RuleDescriptor` for every value in `BuiltinRuleId::ALL` (SCH001–SCH022). A regression test keeps the typed identifiers and descriptor catalogue in one-to-one correspondence and requires each descriptor to include a category, summary, rationale, documentation link, and searchable tags. The registry is deterministic and rejects duplicate IDs.

When `--policy FILE` is supplied, the CLI uses descriptor `default_level` values as the `default` preset and supports `strict` and `advisory` baselines plus per-rule `allow`, `warn`, and `deny` overrides. Without a policy file, existing rule-emitted severities remain unchanged. Policy changes apply only to built-in `SCHnnn` diagnostics; native KiCad ERC findings are not altered. See [rule policy](rule-policy.md).

## Rule boundaries

KiCad native ERC remains the electrical authority. Rust rules must not duplicate pin-type conflicts, undriven power pins, or native unconnected-pin analysis. Rules requiring exact pin-to-net facts must consume KiCad's exported netlist, not infer connectivity from equal label strings.

SCH004 is an opt-in physical-topology contract for profile-declared `direct_wire_pairs`, `common_pin_groups`, `physical_wire_groups`, and `separate_wire_pairs`. It verifies resolved pin anchors are attached to wire segments where required, physical wire-only components are joined or separated as declared, and expected labels are present on their actual physical components. It does not consult exported netlist facts: matching labels never create physical wire edges, and an unconnected pin is not treated as wire-attached.

SCH014 owns logical pin-to-net relationships that require the exported KiCad netlist. This includes component `pin_nets` and `connections.pin.N` expectations, connector pin maps, `common_pin_groups.netlist_connected` (all members must resolve to one exported logical net), and `separate_wire_pairs.netlist_separate` (the two pins must resolve to different exported logical nets). If either logical option is requested through the profile API without a netlist, SCH014 emits a warning that the requested check was not performed. Keeping these checks separate allows a pair of physically separate wire islands with matching labels to pass SCH004 but fail SCH014 when the label joins them into one logical net. Neither rule replaces native ERC.

SCH004’s physical graph follows SCH001’s explicit-junction contract: an endpoint touching the interior of another segment is not joined to that segment unless a junction marker is present. End-to-end wire segments remain connected without an additional junction marker.

SCH005 intentionally checks only connected-wire axis alignment; KiCad native ERC remains responsible for electrical pin compatibility and unconnected-pin findings. It skips pin-axis checks for non-cardinal symbol rotations rather than guessing a horizontal/vertical axis. Other geometry rules use the full finite rotation where their geometry model permits it.

SCH015 checks no-connect marker placement against embedded pin coordinates after applying finite symbol rotations and supported mirrors. It skips the rule if a placed-symbol pin model is incomplete or its transform cannot be resolved. KiCad native ERC remains responsible for electrical unconnected-pin analysis.

SCH009 checks group member origins/pins/fields and selected-unit symbol primitives, plus any wire segment that belongs to a member-pin wire island or intersects the configured frame. It also checks visible glyph bounds for labels whose anchors or glyph rectangles overlap the frame, top-level plain-text glyph rectangles that overlap the frame, the configured group description, other overlapping text boxes, top-level vector graphics (rectangles, polylines, polygons, circles, arcs and Béziers), and embedded PNG/JPEG images. Bitmap bounds are derived from image pixel dimensions, embedded PPI metadata, stored scale, and the KiCad file-version PPI migration rules; unknown or incomplete image encodings remain unresolved rather than guessed. SCH009/SCH012 arc and Bézier containment still use the existing 0.01 mm flattened-path approximation with stroke half-width margin; label/plain-text glyph rectangles use NewStroke estimates. Labels never create physical wire edges. Wire segments overlapping the frame are checked regardless of member-pin connectivity. Free-standing labels/wires outside the frame, unsupported image formats, other non-text-box annotation types and unresolvable symbol transforms remain outside this rule's coverage. Finite non-cardinal symbol rotations are applied to embedded pin and primitive coordinates; SCH005 continues to skip non-cardinal pin-axis checks. SCH012 applies the configured inset to the same member, wire, label, text and annotation families, with frame-overlapping free-standing geometry included.

For SCH013, wire/three-point-arc intersections are analytic: the segment is intersected with the arc's reconstructed circumcircle and candidates are filtered by the directed sweep selected by the start/mid/end points. Cubic Bézier wire crossings use Kurbo's analytic path-segment/line intersection with the original four control points. Top-level and embedded-symbol straight paths and cubic Béziers additionally check wire-to-stroke minimum distance; circular arcs use the 0.01 mm flattened path with a conservative margin. If a wire declares a finite positive stroke width, SCH013 adds it to the graphic width before comparing the half-width envelope, including the circular stroke ring. A wire width of 0 or an omitted width can use a per-wire effective netclass width when `--project` is supplied and the physical wire-only component maps to exactly one exported KiCad net through all of its placed-symbol pins. The resolver unions exact netclass assignments, exact/wildcard project patterns, and committed net-chain assignments; it uses class priority and the Default class only to fill missing wire widths. KiCad's exported effective class name is checked against the project-derived assignment set before a width is accepted. Regex/bus-member pattern expansion, schematic directive labels, rule areas, `Netclass`/`Net Class` label fields, unmapped pins, and components with multiple logical net names remain unresolved rather than guessed. For embedded symbols, the wire portion adjacent to a matching pin endpoint is excluded only within the local stroke-clearance radius, so the remaining wire is still checked; the existing circle body-interior semantics are unchanged, and the declared circle stroke ring is also tested for proximity. Embedded library-symbol `text` and `text_box` objects are also checked as wire obstacles: text uses the existing NewStroke-based estimated glyph bounds, while text boxes use their stored rectangle; both are transformed through the selected unit/convert, symbol rotation and mirror. Free-standing top-level schematic `text` uses the same NewStroke-based estimated glyph bounds. Label glyph bounds remain outside SCH013 because wires may intentionally terminate at label anchors; label collision checks are handled by the separate label rules. SCH013 checks full ellipses as closed stroked bodies and elliptical arcs as open strokes, preserving the distinction so elliptical-arc interiors are not treated as filled obstacles. Ellipse paths use the stored center, major/minor radii and rotation; elliptical-arc paths also use the stored start/end sweep. SCH013 checks schematic bus lines as stroked obstacles; wire-to-bus entry strokes are checked with local endpoint exceptions only at either matching entry endpoint. It also checks both visible no-connect X marker centerlines using KiCad's fixed 48-mil size; the marker pen width is omitted because it comes from schematic settings and is not stored on each marker. SCH013 uses the serialized center, dimensions, scale and rotation to check the actual embedded PNG/JPEG image quadrilateral rather than its enclosing AABB. It also checks hierarchical sheet frame/body clearance with matching sheet-pin endpoint exceptions that do not exempt the rest of a wire entering the sheet. It checks table external borders and header/row/column separator strokes for consistent cardinal table rotations (0°, 90°, 180° and 270°); disabled strokes and merged-cell separators are omitted. Table-cell glyphs use existing NewStroke bounds for 0°, 90°, 180° and 270° text rotations; non-cardinal cell text rotations and inconsistent table geometry are conservatively skipped. The flattened 0.01 mm geometry remains in use for SCH009/SCH012 frame containment and other flattened-curve consumers.

SCH010 estimates visible symbol-field text bounds from the stored field position, font size, angle and justification. It checks field-to-field and field-to-annotation-box overlap, field-to-wire and field-to-pin collisions, label-glyph collisions, and intersections with the field's own or another symbol's embedded outline. A Value field fully contained within a closed symbol primitive is allowed. The bounds are estimates rather than KiCad's exact rendered glyph geometry; the historical maximum-distance-to-body rule and exact gaps are not implemented.

A rule ID is not considered ported merely because it appears in the catalogue. A rule becomes implemented only when it has positive and negative tests and a documented analysis model.

## Profile extensions added by the stacked rule-expansion PR

- SCH009 reports overlapping interiors when two different profile groups claim overlapping schematic rectangles through frame_uuid. Edge contact is allowed; groups that reuse the same frame UUID are treated as sharing one frame; unrelated rectangles are ignored.
- SCH015 supports an opt-in `components.<reference>.attributes.required_no_connect_pins` comma-separated pin-number contract. Profile validation resolves actual transformed embedded-pin coordinates and requires a marker there. Unresolved geometry is reported as unverified; do not treat it as proof that a marker is missing.
- These checks are part of `LintProfile::validate_with_netlist`, so library callers and the CLI use the same behavior. They complement native ERC. In particular, the library electrical pin type `unconnected` is distinct from an explicit no-connect flag and should not be declared in the profile list.
